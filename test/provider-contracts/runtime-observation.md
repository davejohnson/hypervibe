The APIs expose executions of a bound job, including manual runs. They cannot establish whether its scheduler attempted delivery. Unstructured log severity uses Hypervibe's existing error-text detection. Application conventions and provider ingestion delays affect which events are visible. Before emission, excerpts are bounded and stripped of known access tokens, authorization headers, credential fields and recognized credential formats. Arbitrary sensitive information an application writes as ordinary prose can still appear in its excerpt.

## Cloud dashboards and alarms

The same opt-in adds the following reviewed resources. Alarms appear in the native monitoring console. Creating the resources does not select an email, SMS or paging destination. Cloud Monitoring alert conditions, CloudWatch dashboards, custom metrics, log queries and alarms, and Azure scheduled log queries and metric alerts may incur provider charges.

- The AWS CloudWatch dashboard is named `<environment-prefix>-<region>-runtime`. It charts ECS service CPU and memory, recent bound job logs and uppercase application error levels. Its application alarm counts the case-sensitive unstructured levels ERROR, FATAL, CRITICAL and EMERGENCY. An EventBridge rule recognizes STOPPED tasks in the selected cluster and scheduled task families that failed to start or have a nonzero container exit code. A second alarm watches the rule's matched-event count. Missing metric samples leave the alarm quiet. This rule cannot detect a schedule that never launched a task. [ECS metrics](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/available-metrics.html), [ECS task events](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs_task_events.html), [EventBridge monitoring](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-monitoring.html) and [CloudWatch filter syntax](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/FilterAndPatternSyntax.html).
- The Azure Portal dashboard carries the display name `<repository> / <environment> / Runtime` and charts app requests, worker replicas and job executions. Azure Monitor evaluates request timeouts for web services and cumulative replica or job restarts for workers and jobs. A restart alarm can remain active while the affected replica reports a nonzero lifetime count. A separate five-minute console log alert checks the selected workloads and Container Apps environment in their shared workspace. [Container Apps metrics](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/supported-metrics/microsoft-app-containerapps-metrics), [Container Apps Job metrics](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/supported-metrics/microsoft-app-jobs-metrics) and [Azure dashboard template](https://github.com/Azure/azure-quickstart-templates/blob/master/quickstarts/microsoft.portal/azure-portal-dashboard/azuredeploy.json).
- The Google Cloud Monitoring dashboard uses the same display name. Each chart selects one project, region and native Cloud Run service, worker pool or job. Alarms evaluate service 5xx responses, unsuccessful worker health probes, and failed or cancelled job completions over five-minute intervals. [Cloud Run metric descriptors](https://docs.cloud.google.com/monitoring/api/metrics_gcp_p_z#run) and [Cloud Monitoring filters](https://docs.cloud.google.com/monitoring/api/v3/filters).
